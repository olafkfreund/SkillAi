# How AI scoring works (Claude, Gemini, the four dimensions)

Every candidate score in SkillAI is generated by an AI model reading the candidate's CV against the role description and producing a structured judgement. This page explains exactly what the model is asked, what it returns, and how to read the result.

## The four dimensions

Every score has four components, each on a 0–100 scale:

| Dimension | What it measures |
|---|---|
| `technical_skills` | Does the candidate have the hard skills the role needs? Languages, frameworks, tools, methodologies. |
| `experience_level` | Years and depth of experience relative to what the role demands. A senior role wants senior signals — leadership, ownership, complexity. |
| `cultural_fit` | Soft signals from the CV: collaboration, mentoring, mission alignment, type of company they've worked at. This is the noisiest dimension; treat it as a hint. |
| `communication` | Clarity of writing in the CV itself, plus signals like tech writing, public speaking, documentation work. |

The four are combined into an **`overall_score`** (also 0–100) that you sort the ranked list by. Each dimension also has a short **reasoning** string the AI wrote explaining its score — click any dimension to expand the reasoning.

## What the model returns

A scoring run produces this exact JSON shape (validated server-side with Zod):

```json
{
  "overall_score": 84,
  "dimensions": {
    "technical_skills": { "score": 90, "reasoning": "..." },
    "experience_level": { "score": 80, "reasoning": "..." },
    "cultural_fit": { "score": 75, "reasoning": "..." },
    "communication": { "score": 88, "reasoning": "..." }
  },
  "summary": "Strong backend candidate with...",
  "reasoning": "..."
}
```

If the model returns anything that doesn't match this shape, the run fails and the candidate gets a "score failed — retry" pill. We do not parse free-form AI output for scores. Ever.

## Claude is the default; Gemini is the fallback

- **Primary:** Anthropic Claude (`claude-sonnet-4-6`). Higher reasoning quality on nuanced judgement, structured-output guarantees baked into the API. This is what you get unless your tenant has switched.
- **Secondary:** Google Gemini (`gemini-3.5-flash`). Cheaper for high-volume runs. Available as a per-tenant toggle in **Settings → AI**.

You don't pick the model per candidate. The choice is per-tenant — once an admin flips the toggle, every new score uses the selected model. Existing scores are not retroactively rerun.

If both providers are configured, Claude is tried first and Gemini is used if Claude fails (timeout, rate limit, or invalid response). Both are wrapped in retries and timeouts so transient issues don't kill a bulk-upload run.

## Budget is a soft signal, not a fifth dimension

If the role has a `customerDayRate` (your client's budget) and the candidate has a `candidateRate`, the AI is told about the budget when it scores. But:

- **Budget is not one of the four scored dimensions.** No score is reduced because a candidate is over-budget (DEC-009).
- **Within ~10% over budget:** no AI mention.
- **10–25% over budget:** the AI summary will note "may require negotiation".
- **More than 25% over budget:** the AI summary will note "may be misaligned with seniority".
- **Currency mismatch** (role in EUR, candidate in GBP): the AI is told nothing. The UI still shows the margin pill with a warning, but the model doesn't try to reason cross-currency.

Why this design? Because rates are negotiable, but technical fit isn't. We didn't want strong over-budget candidates buried at the bottom of the ranking — your judgement decides whether to push back to the client or pass.

## What the AI does NOT do

- It does not search the public internet for the candidate.
- It does not have memory across runs — every score is independent.
- It does not see your notes, status changes or interview transcripts (those are scored separately via [Interview transcript analysis](/dashboard/help/interview-transcripts)).
- It does not boost internal candidates. INTERNAL is a label, not a thumb on the scale.

## When to rescore

Click **Rescore** on a candidate card to run scoring again. Useful when:

- You significantly edited the role description.
- The candidate uploaded an updated CV.
- You changed the model (e.g. Claude → Gemini) and want apples-to-apples comparison.

Rescoring replaces the previous score; it doesn't keep history. If you need to compare model outputs, screenshot before rescoring.
